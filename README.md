# NexusForge — Autonomous Software Development Platform

## Overview
NexusForge is a self-hosted orchestration platform for autonomous software development. It provides an AI-native interface and a resilient, fail-closed background worker engine for executing validated software tasks in isolated project workspaces.

---

## Architectural Reality

### Backend (`backend/app/`)
- **Framework**: FastAPI (Python 3.10+)
- **Database**: PostgreSQL 15 (asyncpg) or SQLite (`sqlite+aiosqlite`)
- **Data Models**: Unified SQLAlchemy declarative models in `backend/app/models/`
- **Validation**: Pydantic v2 schemas in `backend/app/schemas/`
- **Execution Engine**: Background worker (`backend/worker.py`) with atomic task claiming, OS process PID tracking, and process tree termination
- **Security**: JWT Bearer token authentication (fail closed), multi-tenant ownership enforcement (`enforce_ownership`), path traversal containment, and authenticated WebSocket feeds

### Frontend (`src/`)
- **Framework**: React 18 + TypeScript 5
- **Build Tool**: Vite
- **Design System**: AI-Native dark theme with modern typography and RTL/LTR internationalization support
- **State & Routing**: React Router v6, Axios
- **Auth**: Fail-closed `ProtectedRoute` validating tokens against `/api/auth/me`

---

## Security Model & Hardening

1. **Fail-Closed Authentication**:
   - Missing, invalid, or expired tokens return `401 Unauthorized`.
   - Inactive users are rejected.
   - Frontend purges local storage and redirects to `/login` immediately upon authentication failure.
2. **Multi-Tenant Isolation (IDOR Protection)**:
   - Every project, task, artifact, and execution endpoint verifies ownership before reading or mutating resources.
   - Cross-tenant access attempts return `403 Forbidden`.
3. **Workspace Path Containment**:
   - All workspace file operations are resolved canonically and checked via `.is_relative_to(workspace_dir.resolve())`. Path traversal attempts (`../`, absolute paths, symlink escapes) are rejected with `400 Bad Request`.
4. **Disabled Host Terminal Execution**:
   - The general-purpose host terminal execution endpoint (`POST /projects/{id}/terminal/exec`) is permanently disabled (`403 Forbidden`) to eliminate host Remote Code Execution (RCE) vectors.
5. **Race-Safe Worker Claiming**:
   - Atomic conditional SQL transitions (`UPDATE tasks SET status='running' WHERE id = :id AND status IN ('queued', 'planning', 'ready')`) and PostgreSQL `FOR UPDATE SKIP LOCKED` prevent duplicate task execution across multiple concurrent workers.
6. **Execution Concurrency Bounded**:
   - Active executions are gated against `MAX_CONCURRENT_WORKERS`.
7. **Real Process Control**:
   - Worker execution tracks the OS PID of running processes. Cancellation, timeout, or worker retirement terminates the actual OS process tree (`taskkill` on Windows, `killpg` on POSIX).

## Quick Start

### 1. Environment Setup
```bash
# Clone the repository
git clone https://github.com/aminvahdat/NexusForge.git
cd NexusForge

# Copy environment template
cp .env.example .env
# Ensure JWT_SECRET_KEY is at least 32 characters long
```

### 2. Run with Docker Compose
```bash
# Build and start all services
docker compose up -d

# Check service status
docker compose ps

# View backend logs
docker compose logs -f backend
```

### 3. Local Development

**Backend:**
```bash
# Install dependencies
pip install -r backend/requirements.txt

# Run backend API
python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload

# In another terminal, run worker
python backend/worker.py --worker-id worker-01 --hostname localhost
```

**Frontend:**
```bash
# Install dependencies
npm install

# Start frontend development server
npm run dev
```

## Running the Automated Test Suite

The test suite validates foundation models, security boundaries, worker concurrency, and real end-to-end execution:

# Build frontend production bundle

## API Summary

| Endpoint | Method | Description | Auth Required |
| :--- | :--- | :--- | :--- |
| `/api/auth/register` | `POST` | Register a new user | No |
| `/api/auth/login` | `POST` | Authenticate and obtain JWT token | No |
| `/api/auth/me` | `GET` | Get current authenticated user | Yes |
| `/api/projects` | `GET` / `POST` | List or create projects owned by user | Yes |
| `/api/projects/{id}` | `GET` / `PUT` / `DELETE` | View, update, or delete project (Ownership Enforced) | Yes |
| `/api/projects/{id}/tasks` | `GET` / `POST` | List or create tasks under a project | Yes |
| `/api/tasks/{id}` | `GET` / `PUT` / `DELETE` | View, update, or delete task (Ownership Enforced) | Yes |
| `/api/artifacts/project/{id}` | `GET` | List artifacts generated by project tasks | Yes |
| `/api/workers` | `GET` | List active registered worker nodes from DB | Yes |
| `/api/execution/{id}/cancel` | `POST` | Cancel execution and terminate OS process tree | Yes |
| `/api/execution/{id}/retire` | `POST` | Terminate process and retire worker to idle | Yes |
| `/ws/{client_id}` | `WebSocket` | Real-time execution logs (JWT & Ownership Verified) | Yes |
